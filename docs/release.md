# Releases

Versions follow semantic versioning; `v1.0.0` closes Phase 6. Until then releases are
pre-releases (`v0.1.0`, `v0.2.0-rc.1`), tagged by the Author once the `Desktop` workflow is
green on `main`.

## How a release happens

1. Update the version in `apps/desktop/package.json`, `apps/desktop/src-tauri/tauri.conf.json`
   and `apps/desktop/src-tauri/Cargo.toml`, move the `Unreleased` section of `CHANGELOG.md`
   under the version, and write `docs/release-notes/<tag>.md` in both languages (start from
   `TEMPLATE.md`).
2. Tag and push: `git tag v0.1.0 && git push origin v0.1.0`.
3. The `Release` workflow builds the sidecar bundle, fetches the Node runtime for each target,
   builds the installers on Ubuntu 22.04, Windows and macOS (universal) and attaches them to a
   draft GitHub release with the notes. The Author reads the draft, downloads one installer per
   platform, tries the first run, and publishes.

Installers: `.deb`, `.rpm`, `.AppImage` (Linux), `.msi` and NSIS `.exe` (Windows), `.dmg`
(macOS). Each carries the Node runtime (about 50 MB compressed) and the bundled narrators,
prompts, style rules and evals.

## Signing

Unsigned builds work but warn on first launch (SmartScreen, Gatekeeper). Signing is switched on
by adding repository secrets; the workflow passes them to `tauri-apps/tauri-action`, and
nothing changes in the repository.

| Platform | Secrets | Notes |
| --- | --- | --- |
| macOS | `APPLE_CERTIFICATE` (base64 .p12), `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (app-specific), `APPLE_TEAM_ID` | Developer ID Application certificate; notarization runs when the Apple ID secrets exist. |
| Windows | `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID` plus the Trusted Signing settings in `tauri.conf.json` (`bundle.windows.signCommand`) | Azure Trusted Signing, no certificate file in CI. A classic `.pfx` works too through `WINDOWS_CERTIFICATE` / `WINDOWS_CERTIFICATE_PASSWORD` and `certificateThumbprint`. |
| Linux | none | Packages are not signed; the release page carries SHA-256 sums generated by the action. |

The app has no auto-updater, so no updater key pair is needed yet; when one is added, its public
key goes into `tauri.conf.json` and the private key into `TAURI_SIGNING_PRIVATE_KEY`.

## What never goes into a release

Keys, the Author's private stories, generated manuscripts, eval results that name private
texts. The sample projects are the only stories shipped.
