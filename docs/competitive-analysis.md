## Verdicts

**Sudowrite** [S]. The broadest feature set and the only vendor with a fiction-tuned model. Its weaknesses for a serious long-form author are the things it does not show: what went into the prompt, how the Bible was used, why a passage came out the way it did; plus cloud storage, credit pricing and a Brainstorm that does not read the Bible. We match Write, Story Bible, Describe, Rewrite, Expand and Canvas feature by feature and add transparency; we do not claim a custom model.

**Novelcrafter** [S]. The closest model for context control: alias tracking, four inclusion modes, relations, editable prompts with a preview. It is web-only without an offline mode, has no token meter, and exports no EPUB. Our activation rules, prompt files and inspector follow its lead with files on disk and a visible budget.

**NovelAI** [S]. Its Lorebook activation (keys, regex, `&`, Always On) and the Context Viewer with per-section token budgets are the reference for our activation and inspector. Not a long-form tool: no Bible structure, no planning, cloud models only.

**Ghostwriter** [V]. Small, honest, MIT: Markdown folders, git built in, a deterministic lint of AI tells whose rule schema (name, level, message, tokens or pattern) we adopted in spirit and extended with Russian morphology and a tested fault set. Electron, not Tauri; unsigned builds; 15 commits.

**Open-Write Studio** [V]. The most ambitious pipeline (bible, voice, architect, writer, five critics, editorial, verify, assemble, adversarial read, finalize) and the only peer on Tauri 2. Its changelog documents the cost of a Python sidecar under Tauri: port leaks, orphan processes, startup hangs, a CORS origin, Playwright unable to drive the shell, unsigned installers and a disabled updater. Our core is TypeScript in-process, which removes the sidecar class of problems; its hash-bound critic findings and the "minimum three located findings" gate shaped our critic contract.

**local-writing-app** [V]. The best ledger design we found: CSV, frozen cost at write time, never re-priced, header-keyed columns, scope rollups; AI off by default; keys in the OS keyring with an honest fallback. Our `history/calls.jsonl` follows the same rules. It deliberately omits export and planning.

**Orison Space, Vela, CharacterArc** [V]. All Electron. Orison (Apache-2.0, stalled since July 2026) has a Claude-Code-compatible skill and agent layout and a Suggest mode that returns diffs instead of writing files, which matches our suggestion model. Vela (GPL-3.0) adds a local vector store over imported reference material; we keep deterministic retrieval first and leave an embeddings seam. CharacterArc (MIT, very active, prose in SQLite rather than files) has a skill-matching pipeline and a gated "de-slop" workflow with deletion caps and a whitelist, close to our de-AI rewrite plus whitelist.

**Tauri in the field.** Of nine products, one (Open-Write) runs on Tauri 2 and reports mostly sidecar and signing pain; six run on Electron. Nothing in the reports argues against Tauri for a TypeScript in-process core; the ADR keeps Tauri as the default and names Electron as the documented fallback.

## Decisions

### Ten things we must have at launch

1. Write in four modes (continue, guided, scene, chapter) from a manuscript window plus rolling summaries, with streamed suggestions and accept / retry / discard.
2. A Story Bible with aliases in two languages, inflection-aware activation, pins, always-on and secrets.
3. The chronicle: machine-readable state, reader-safe log, hidden block, proposals applied only on confirmation, a handover command.
4. A context inspector on every generation with a visible token budget.
5. Describe in sensory layers with Weave as a diff.
6. Rewrite operations as per-paragraph diffs with a voice lock, including de-AI.
7. The narrator system: Gwen profile, three storytellers with a real d20, harshness 1–6, ratings as ceilings, hard limits in code.
8. The bilingual tier-one linter with a tested fault set and a project whitelist.
9. Plain files on disk with JSON Schemas, migrations, a trash folder and an append-only cost log; no account, no telemetry.
10. Headless harness mode: the repository works from Claude Code alone (MCP server, skills, agents, hook), with or without an API key.

### Five things we will do better than anyone

1. **The narrator system** (Section 5): storytellers, fate harshness, ratings, lore research, the chapter pipeline and the chronicle. No competitor has a pacing engine or a state tracker of this shape.
2. **The bilingual AI-tell linter** (Section 7): Russian and English, deterministic and tested, with morphology-aware phrase matching and a seeded fault set every rule must catch; competitors are English-only or LLM-only.
3. **The context inspector**: every layer, every Bible entry with the alias that triggered it, every trimming decision, every lesson and roll; Novelcrafter previews, NovelAI shows a bar, nobody explains why.
4. **The chronicle**: state as YAML the planner reads, a reader-safe log, a hidden block that never leaks, a handover for continuing elsewhere.
5. **Lessons from the Author's own edits** (Section 6): dated, provenance-carrying rules distilled from real diffs and notes, retrieved by category into every prompt, confirmed by the Author, never silent.

Each decision has an ADR in `docs/decisions/`.
